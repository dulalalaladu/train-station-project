# 附录：向腾讯云（TRTC）与微信硬件团队确认的问题清单

> 本文随 [ADR-0005 对讲通道](./0005-intercom.md) 发布，可**整篇直接转发**给腾讯云售前 / 微信硬件接入团队。
> 文中不含账号、密钥、站场位置等敏感信息。编制日期：2026-10-23。

## 一、项目背景（给对方的一段话）

我们在建设一套「巡检机器人（四足机器狗）与作业人员之间的语音互动系统」。作业人员通过**微信小程序**与机器人进行语音对讲；机器人端是一台 **NVIDIA Jetson Orin NX（aarch64）**，运行 **Ubuntu 22.04 + ROS 2 Humble**，通过 5G CPE / Wi-Fi 6 联网，使用外置 USB 麦克风阵列（硬件回声消除）和功放喇叭。当前基线是自建半双工对讲；我们正在评估 TRTC 全双工作为升级方案。试点阶段部署在腾讯云国内区域，终局可能运行在铁路局内网。

我们已核对到的公开信息（请据此纠正）：

- TRTC 小程序方案：企业主体小程序 + 开放类目 + 订阅 TRTC 包月套餐（`https://cloud.tencent.com/document/product/647/116548`）。
- SDK 下载页「服务端 SDK」栏有 **Linux SDK**：「用于服务端推拉流、机器人/数字人等场景，支持 C++、Go、Python、Java、Rust。服务器要求 glibc ≥2.28；提交申请前请先购买旗舰版及以上包月套餐」（`https://cloud.tencent.com/document/product/647/32689`）。
- 包月套餐表：基础版 625 元/月，旗舰版 6,250 元/月（`https://cloud.tencent.com/document/product/647/17157`）。

## 二、问题清单 — 腾讯云 TRTC 售前

编号以 Q 开头；**★ 为必须在评估前得到书面答复的阻断项**。

### A. 狗端 Linux SDK（最关键）

| # | 问题 |
|---|---|
| Q-1 ★ | 「Linux SDK」是否提供 **aarch64（ARMv8）** 构建？目标环境为 Ubuntu 22.04（glibc 2.35）、JetPack 6、Linux 5.15 (Tegra)。若有，请给出支持的发行版/内核/依赖库清单；若无，是否有路线图与时间点？ |
| Q-2 ★ | 该 SDK 是否**允许部署在终端设备（机器人）上**，而不仅是服务器？是否有面向嵌入式 / IoT / 机器人的专用 SDK 或「设备端 SDK」？（我们看到的公开描述是「服务端 SDK」。） |
| Q-3 ★ | **授权方式与计费**：按 SDKAppID、按设备装机量，还是按用量？「必须先购买旗舰版及以上」是硬性前置，还是可由商务协商（例如先用体验版 / 基础版做 PoC）？申请表提交后的审批周期？ |
| Q-4 | 是否有 **C 接口**（头文件、ABI 稳定性）？我们的音频环路为 ROS 2 节点（Python / C++），希望了解 C++ API 与 Python 绑定的成熟度与示例。 |
| Q-5 | 自定义音频采集与播放：是否支持 **外部 PCM 输入/输出（16 kHz、16 bit、单声道）**？能否**关闭内置 3A（AEC / NS / AGC）**，只使用我们的硬件 AEC？是否需要回灌扬声器参考信号？ |
| Q-6 | 音频编码：Opus 码率范围、纯音频模式的带宽占用、丢包 20% 下的表现、端到端延迟的**典型值与测量方法**（贵司是否有 aarch64 实测数据）。 |
| Q-7 | 版本支持周期与升级策略（Ubuntu 22.04 / ROS 2 Humble 生命周期至 2027-05），以及 ABI 变更通知方式。 |

### B. 小程序侧

| # | 问题 |
|---|---|
| Q-8 ★ | 启用小程序 SDK（`live-pusher` / `live-player` 的 `mode="RTC"`）所需**最低套餐**：入门版（0 元）是否足够？还是必须基础版及以上？（`116548` 页要求订阅包月套餐，`17157` 页入门版为 0 元，两页口径需澄清。）「小程序通话加速」仅尊享版及以上，是否影响弱网下的对讲质量？ |
| Q-9 ★ | 小程序类目：除官方开放类目表外，贵司是否有**类目申请指导**？针对「巡检机器人对讲 / 设备运维」这类场景，贵司建议选择哪个类目、需要提供什么资质（例如「IT科技 › 多方通信；音视频设备」是否要求增值电信业务经营许可证）？贵司能否协助与微信侧沟通？ |
| Q-10 | 小程序 `live-pusher` 的 `url` 仅支持 `rtmp` 格式：TRTC 小程序方案的推拉流地址如何生成（鉴权、有效期、是否需要业务后端签发 UserSig）？ |
| Q-11 | 在 iOS / Android 微信中，后台、锁屏、来电打断时的推拉流行为与官方建议的处理方式。 |

### C. 录制、转写与审计

| # | 问题 |
|---|---|
| Q-12 ★ | 是否支持**云端音频录制**（单路混流 / 分路），输出格式（mp3 / aac / ogg）与落地存储（COS）**区域**？能否指定存储在国内某区域并设置保留策略？ |
| Q-13 | 我们需要把对讲音频**实时送给第三方语音转写**（16 kHz PCM）。可选路径：① 服务端 Linux SDK 加入房间拉取 PCM；② 旁路推流 RTMP；③ 云端录制回调后离线转写。请说明各路径的延迟、计费与限制。 |
| Q-14 | 房间内各路音频是否可获得**时间戳与说话人标识**（用于对讲审计：谁、何时、说了什么）？ |
| Q-15 | 信令 / 房间事件日志（进房、退房、质量指标）的保留时长，以及 REST API 的查询能力（「房间通话调查」）。 |

### D. 计费与商务

| # | 问题 |
|---|---|
| Q-16 ★ | **语音通话**的准确单价与计时口径。套餐页出现「7 元/千分钟」，请明确它对应语音通话还是视频通话；仅 1 人在房时的计费；一个房间内 1 台机器人 + 1～2 名调度员 / 作业人员的典型计费示例。 |
| Q-17 | 预估用量：试点 1～3 台机器人，每台每日对讲 ≤2 小时，30 分钟不断线场景；请给出 **1 年总价**（含旗舰版套餐、超量部分、录制费用）与企业客户折扣方案。 |
| Q-18 | 体验版（7 天）与 10,000 分钟免费时长包能否用于 aarch64 设备的 PoC？是否可延长 PoC 周期？ |

### E. 网络、私有化与合规

| # | 问题 |
|---|---|
| Q-19 ★ | **私有化部署**：终局运行环境是铁路局内网，不允许访问公网。贵司是否提供 TRTC **私有化 / 专有云**版本？若不提供，是否支持专线 / 白名单出口？ |
| Q-20 | 需要放通的**域名、IP 段、UDP / TCP 端口**；5G CPE / 企业防火墙环境下 UDP 受限时是否有 TCP 回退；是否支持 HTTP 代理。 |
| Q-21 | 数据合规：音视频数据中心所在地域、是否出境、等保级别、对**国密算法**的支持；贵司对「交通运输数据」类客户的合规材料。 |
| Q-22 | SLA、技术支持响应时间，以及面向机器人场景的**售前 PoC 支持**（是否有技术团队可远程协助 Jetson 联调）。 |

## 三、问题清单 — 微信硬件接入团队（方案 A，次要）

仅当业主要求评估「手机微信原生来电」方案时发送。

| # | 问题 |
|---|---|
| W-1 ★ | 「小程序音视频通话 SDK（Linux）」安装包的架构（aarch64）与依赖库清单；是否已在 Jetson（Ubuntu 22.04）上有成功案例？ |
| W-2 ★ | 设备唯一性要求（eMMC 写入不可更改的唯一 key）对**非 eMMC（如 NVMe）存储**的设备如何满足？ |
| W-3 | 现行**设备 license 收费规则**：2023 年使用手册说明体验 license 用完后需购买套餐，社区有开发者称无需购买，请以官方答复为准。 |
| W-4 ★ | 通话媒体是否可在**服务端或设备侧合法录音留存**？是否有官方接口？机器人场景是否允许设备**自动接听**手机微信呼叫？ |
| W-5 | 「寄送设备验证」的「设备」对机器人形态如何认定：能否仅寄送机载计算单元 + 音频模组 + 演示视频，而非整机？ |
| W-6 | 是否允许一个小程序同时绑定多台机器人，并由多名调度员授权（设备组 `groupId`）？ |
